## Library tab (`msr/library.py`, `msr/charts.py`, `msr/library_window.py`)

Size per site / channel / month of the recordings, and (since the manage feature) a way to clean up. **The scan and charts stay read-only**; everything that changes files lives in `msr/library_actions.py` and is reached only through the review window (`library_dialog.py`). Never add a one-click delete.

- **Read-only and cheap by default.** The scan only lists folders (`os.scandir`) and reads sizes and times from the entries; it never opens a video and never runs ffprobe. Recorded time is opt-in (**Count hours**): `.meta.json` sidecars first, ffprobe only if the user agrees, one file at a time, rate-limited, cancellable.
- **Background thread, never Tk.** `ScanJob` talks to the UI through a `queue.Queue` that `LibraryPanel._poll` drains with `after`. The tab scans the first time it is opened (`activate()`), not at startup. Do not add another header or bottom-bar button: both are already full at the minimum window width, which is why this is a tab.
- **Where things live.** The only file written is the remembered-durations cache `library_cache.json` in the data folder (git-ignored, keyed by path + mtime + size). Nothing is ever written in the recordings folders. Tests use temp trees.
- **Public repo.** `summary_text`, `to_dict` and `--json --library` carry channel names and sizes only: no absolute paths (extra folders are labelled "Other folder N"). Channel folder paths exist in memory only for **Open folder**.
- **Layout it understands.** `<streams_dir>/Recorded|Processed|PendingDeletion/<platform>/<channel>/...` (folder names matched case-insensitively), the clips dir (`clips_dir` or `streams_dir/Clips`), custom URLs as `custom/<site>/<user>`. Reparse points (junctions, symlinks) are skipped, in-progress `.ts` / `.part` files are counted as raw, channels not in the roster are flagged, not hidden.
- GUI names inside `main_gui` follow the rule above (`library_panel`, `_library_panel`, `_library_tab_opened`, `_library_busy`, `_library_purge_settings`, `library_data_dir`).

### Managing files (the safety rules; do not weaken them)

- **Default is reversible**: *Move to PendingDeletion*. MSR purges that folder only **at app start** (`purge_old_pending_files`, `Cleanup/auto_purge_days`), aging by `max(mtime, ctime)`; a rename keeps both, so the mover **resets mtime to now** and keeps the original in `library_moves.json` (restore puts the date back). Recycle Bin (`SHFileOperationW`, `FOF_ALLOWUNDO`, no new dependency) is offered only when the registry shows the bin's limit and the plan fits; **Delete permanently** needs the typed channel name or `DELETE`.
- **`Guard.check` runs twice** per file: when the plan is built (dry run) and again right before each file. It refuses anything outside the Processed / Recorded / PendingDeletion / Clips folders (extra Library folders are scan-only), links/junctions on the way, files directly in a top folder, unknown file types (only recordings, raw/partial, clips, screenshots, `.meta.json`), files changed since the preview, files modified in the last 10 minutes, and **any channel or file the recorder is working on** (`busy_from_status` over `recorder.status_dict`; if that callback fails everything is blocked).
- **No action while a scan or another action runs**, or if the action log cannot be written. Every action appends JSON lines to `library_actions.log` and a summary goes to the Log tab. `library_actions.log` and `library_moves.json` are in the data folder and git-ignored.
- Tests use temp trees only and inject fake movers (`ManageContext.deleters`); `tests/test_gui_smoke.py` runs the real hidden app with a fake mover. Never point a test at a real library.

## Agent control (`msr/control.py`, `msr_ctl.py`)

Everything the GUI does must stay reachable without it. One `Controller` (no tkinter) runs every command against an **app adapter**: `_GuiControlApp` inside `main_gui`, `HeadlessApp` (the `--headless` loop) or `OfflineApp` (nothing running: `msr_ctl.py` edits the files). A new GUI feature needs a `cmd_*` here too (and a row below), or a line saying why not.

- **Wire format.** TCP on `127.0.0.1`, random port, one JSON line per connection: `{"token": "...", "cmd": "status", "args": {...}}` -> `{"ok": true, "result": ...}` or `{"ok": false, "code": "...", "error": "..."}`. Port and token come from `msr_control.json` in the data folder (written atomically at start, POSIX 0600, deleted at exit only by the pid that wrote it, git-ignored). The token is checked with `hmac.compare_digest`; a bad one is logged without the token. Never bind anything but loopback, never put the token in a log, argv or `msr_status.json`.
- **Codes** (stable, for agents): `auth`, `bad_request`, `unknown_command`, `not_found`, `ambiguous`, `invalid`, `conflict`, `busy`, `confirm_required`, `not_running`, `not_recording`, `unsupported`, `nothing`, `write_failed`, `failed`, `internal`. `msr_ctl.py` exit codes: 0 ok, 1 refused, 2 usage, 3 not running, 4 auth, 5 confirm, 6 timeout.
- **Threads.** Commands run on a server thread. In the GUI, roster edits go through `_on_tk` (a `root.after` + wait) so `channels`, the tree and `channels.json` change together; recorder calls (`start_channel`, `stop_channel`, `check_now`, `set_poll_interval`) run on the server thread exactly like the GUI's own background helpers. `start_recording(interactive=False)` is the dialog-free start (refusals raise `ControlError`, warnings go to the log). Never open a dialog from a control path.
- **Adding starts monitoring.** `Controller._monitor` runs after `channel_add` / `channel_enable` / `record_start`: a running session gets `start_channel`; headless with no session (`auto_session`) starts one, unless the user ran `stop` (`paused`, cleared by `start` / `record_start`). The GUI never starts a session by itself (Start Recording stays the user's). `parse_add_text` turns `platform:name`, bare names (Kick) and channel URLs into keys; a lone platform word is an error; a multi-name add is all or nothing.
- **Headless loop.** `HeadlessApp.run()` owns the main thread: `recorder.run()` blocks until a stop; `stop` (control) calls `recorder.stop()` and finishes cleanup on a thread; `quit` sets `should_stop` so the main thread does the full `finish_headless_session`. Recording of the enabled channels still starts at once. Ctrl+C behaves as before.
- **Status file.** `StatusWriter` rewrites `msr_status.json` every `[Control] status_interval_seconds` (3) and on `poke()` after each command. Channel names go through `status.display_name` (custom URLs -> host). Settings shown by `config_get` are masked when `history.is_sensitive`.
- **Confirmation.** Library actions, history restore and update install need `confirm=true`; a permanent delete needs `confirm` equal to `Plan.confirm_word` (the GUI's typed word). A library action with no filter at all is refused. The `Guard` rules above apply unchanged (busy channels via `busy_from_status`).
- **Offline edits.** `msr_ctl.py` falls back to `OfflineApp` only when no copy answers **and** `status.is_running(streams_dir)` is false; otherwise it exits 3 and changes nothing.
- **Off switch.** `[Control] enabled = false` or `MSR_CONTROL=0`. Tests: `tests/test_control.py` (fake recorder, temp data folders).

## Instant clips (`create_clip` in `msr/worker.py`)

Kick/live MPEG-TS PCR often sits at ~10000s while the `.ts` on disk is only minutes long. Twitch can also report `format.duration` as the **last PCR** (e.g. 12686) instead of elapsed file time (e.g. 67). `_elapsed_media_duration()` must convert that before computing the cut; otherwise a 15s Clip Now seeks to ~65s of a 67s file (powdur clip was **2.6s**) and screenshots miss the frame.

**Correct:** convert duration to elapsed if it looks like last-PTS (`duration > start_time` and `start_time >= 1000`). Probe the last video keyframe at or before `(elapsed - clip_seconds)`, then input `-ss` to that keyframe’s **elapsed** time (`kf_pts - format.start_time`), tiny undershoot (~0.05s), never past the keyframe. `-c copy`, `-t` extended to the live edge, `-avoid_negative_ts make_zero`. No output `-ss`, no `-copyts`. If elapsed is far behind the file’s birth time (Kick HLS ad PCR reset; nicklee 2024s vs 5990s), **ignore duration** and probe/cut with `-sseof` instead — `-ss` from the start hits the first occurrence of the new clock, minutes behind live.

**Wrong (causes a frozen first GOP):** `-copyts` plus output `-ss {raw PCR pts_time}`. Audio starts at 0s, video at ~2s (Kick GOP). Verified on binxbasilisk 15s clips: bad cut video start **1.99s**; after the elapsed-seek fix, **~0.18s** (AAC/B-frame delay, not a freeze).

15s clips are the harshest test because a 2s GOP is a large fraction of the file.

## Experimental live previews (`experiment/status-previews`)

Status-tab stills from the live `.ts`. Constants in `msr/gui.py`: `PREVIEW_W`/`PREVIEW_H` (160×90), `PREVIEW_BIG_W`/`PREVIEW_BIG_H` (480×270), `PREVIEW_MS` (4000).

- `create_preview_frame` / `create_screenshot` in `msr/worker.py` — seek-before-EOF (`-sseof` first, elapsed `-ss` fallback). Do **not** prefer `-ss duration-N` for screenshots: after a Kick ad PCR reset that seeks minutes behind live (preview stays current). PNG for previews (tk.PhotoImage has no JPEG), `CREATE_NO_WINDOW`. Preview failures are quiet.
- **Clip Now** after a PCR reset: if ffprobe elapsed is far behind file birth (`_elapsed_matches_file_age`, nicklee 2024s vs 5990s), treat duration as missing and probe/cut with `-sseof` like the no-duration path. Trusted elapsed still uses keyframe elapsed `-ss` (Kick/Twitch PCR). No output `-ss`, no `-copyts`.
- Worker **Recording** status includes **`raw_file`**. The GUI preview loop must use that path. Do **not** `listdir` recording folders on the 1s IO tick. Fallback `find_active_recording_file` is OK on the 4s preview pass if `raw_file` is missing.
- Grab flags: `-threads 1 -skip_frame nokey` before `-i` (about 2-10x less CPU; the picture can be up to one key-frame interval older than live). Seek order is `preview_state.LADDER` (`-sseof -3`, `-sseof -6`, elapsed `-ss`, then a plain decode as a safety net); a channel remembers its working rung because a stream with key frames 4 s apart never yields a frame at `-3`. When every rung fails the channel backs off (`PreviewState.due`).
- A tile older than 10 s shows its age (`name \u00b7 12 s`) with the theme `warn` border; a channel that stopped recording keeps its last frame 90 s marked `ended`. `_tick_previews` does nothing while `preview_wrap` is not viewable (tab hidden, window minimised or in the tray) and `_kick_previews` ticks at once on `<Map>` / tab change. `tests/test_preview_strip_gui.py` drives the real hidden window with a fake recorder and grab.
- Grab on a daemon thread, one ffmpeg at a time; skip a channel if Clip/Screenshot is in flight on it. Keep `PhotoImage` refs (`_preview_photos`, `_preview_big_photo`) or Tk drops the picture.
- Click tile / status row / roster stay on the same channel (`_sync_nav`). **Never** call `update()` or `update_idletasks` from `<<TreeviewSelect>>` or `_sync_nav` — that nested the Tk loop and froze the GUI on Windows. `see()` / canvas scroll only in `after_idle`. Hold `_nav_lock` around `tree.move` in `_reorder_status_rows`.

## Left roster panel (`ui/left-panel`)

- Pure logic lives in `msr/channel_panel.py` (tested in `tests/test_channel_panel.py`); widgets are still built in `main_gui`.
- Roster iids are `c:<channel key>` (group headers `h:<group>`). Never map rows by display text: the name column shows the bare name and the platform is a separate tag. channels.json keys are unchanged.
- Groups are titled **Recording**, **Watching** (enabled, not recording) and **Off** (disabled; collapsible). Internal group ids stay `recording` / `enabled` / `disabled`, and the collapse flag is still `roster_disabled_collapsed` in window_state, so old state files keep working. Manual order is kept inside groups. View toggle is `roster_view` (all/enabled/live); the old `roster_enabled_only` is still read.
- **No status dots** (removed on request; do not re-add). Live state (`channel_live_state` from `recorder.status_dict` merged with presence by `msr.presence.combined_state`) only drives the Recording group and the **Live** filter, refreshed on the 2.5s `refresh_status` tick (`_roster_live_tick`). The tree is rebuilt only when the grouped/filtered layout changes.
- **Presence** (`msr/presence.py`): `PresenceStore` holds `{live, viewers, since, source}` per key for ALL channels. Sources: `KickPushListener` watches every Kick channel (enabled = `_wanted`, wakes the worker; disabled/stopped = `_watch`, presence only and must never call `check_now`/start anything), and `PresencePoller` polls DISABLED channels only (Kick `/api/v2/channels/{slug}` via curl_cffi, Twitch via `check_stream_streamlink`), one at a time spread over ~10 min, failures silent. Enabled channels are never polled by presence. Push needs a running session; the poller runs whenever the GUI is open.
- **Kick realtime transport** (`msr/kick_realtime.py`): no hard-coded Pusher key (the old `32cbd69e...` key died, error 4001). Every (re)connect POSTs `web.kick.com/api/v1/realtime/connection` like the web client; Centrifugo is primary (guest token from `/v1/realtime/auth/connection`, JSON protocol: `connect` -> `subscribe {"channel":"channel.<id>"}`, answer server ping `{}` with `{}`, `refresh` the ~45 min token), Pusher with the returned `app_key`/`cluster` is the fallback. Publications are `{"event": "App\\Events\\StreamerIsLive"|"...StopStreamBroadcast", "data": "<json>"}` on `channel.<id>`, normalised to Pusher shape and parsed by `parse_kick_push_event`. Max 128 subs per connection (error 106); MSR caps at 120. Connection failures warn at most hourly, back-off up to 10 min; polling is unaffected.
- Kick push: slugs that never confirm `subscription_succeeded` (failed id lookup, lost frame) are retried by the `kick-push-resubscribe` sweep with 2-30 min back-off. Before this they stayed unsubscribed until the next reconnect (the lettyvision symptom). Id lookup tries `_` -> `-` slug variants.
- Amber cookie badge = `cookie_badge()`: auth-error text in a worker Error detail, an expired auth cookie for the site, or Fishtank with no cookie and no config login. Drawn on the side canvas, enabled rows only.

- **Dialog title bars:** `msr/wintheme.py` `set_title_bar_dark(win, dark)` (DWM attribute 20, then 19, on the `wm_frame()` HWND after `update_idletasks`, then SWP_FRAMECHANGED to repaint). The main window, the Add channel dialog, and the custom poll/clip `simpledialog` prompts (via `watch_new_dialogs` before the blocking call) use it; `apply_theme` re-themes open dialogs. Native `messagebox` dialogs are OS-owned and can't be themed.

## Themes (`msr/themes.py`)
- **Never write a colour in code.** Use `themes.current()["token"]` (or `Muted.TLabel` / `Warn.TLabel` / `Error.TLabel` / `Ok.TLabel` styles). A new colour need means a new token in `COLOR_TOKENS` and a value in every theme. `tests/test_theme_guard.py` scans `msr/*.py` for hex and named colours (one explained allowlist entry) and `tests/test_themes.py` checks every theme for completeness and WCAG contrast (`TEXT_PAIRS` at least 4.5:1, `GRAPHIC_PAIRS` chart colours at least 3:1).
- **Add a theme from a published palette** (Omarchy-style: bg, fg, selection, accent, red, green, yellow, blue, magenta, cyan): one dict in `msr/theme_palettes.py` with a `credit` (port URL + licence, upstream + licence; `tests/test_omarchy_themes.py` checks it and that `THIRD_PARTY_NOTICES.md` lists it, so add its row to THIRD_PARTY_NOTICES.md too). `themes.from_palette()` nudges unreadable colours to the contrast rules and picks six distinct chart colours; Start/Stop and OK/Error must stay clearly different. **Hand-made theme:** one `_add(_make("Name", dark_flag, bg=..., ...))` entry in `msr/themes.py`. `_make` fills tokens you leave out (hover, selection, caption, chart tones); `**_SITES_DARK` / `_SITES_LIGHT` / `_SITES_HC` give the per-site chart colours. The Theme window, config migration and tests pick it up from the list.
- Applying: `apply_theme()` in `main_gui` calls `themeui.apply_ttk`, recolours the classic Tk widgets, the log tags, the roster, menus, the caption (`wintheme.set_title_bar_dark` uses the theme's dark flag and, on Windows 11, its caption colours) and `LibraryPanel.refresh_theme()` (charts, site colours, tooltips). Code that draws with its own colours (canvases, tooltips, dialogs) must read `themes.current()` when it draws, not at import.
- Config: `[GUI] theme = <name>` is written only when the user confirms a theme (it is deliberately not in `DEFAULT_CONFIG`, so migration can see it is unset). `dark_mode` is still read (window_state.json first, then config.ini) and kept in step. `true` migrates to PowerShell Blue, `false` to Light. An unknown saved name falls back the same way.
- User themes: `<data>/themes/*.json` (git-ignored), max 20 files of 20 KB, `{"name", "base", "dark", "colors"}`; only known tokens with `#rrggbb`; a bad file is ignored and listed in the Theme window. Built-in names cannot be replaced.
- `tests/test_theme_smoke.py` launches the real window hidden and applies every theme through the Theme window, checking widget and chart colours, the tooltip, the saved config and the bottom-bar width at 1100 and 1060 px.

## Other behavior that must not regress

- **Remove channel** calls `StreamRecorder.remove_channel()` so the worker is killed; do not only delete the GUI list entry.
- **Complete toasts** are edge-triggered (`_notified_complete`). Do not notify every 2.5s refresh while status stays Completed.
- **Status table** updates existing rows in place. Do not delete-and-rebuild the tree every tick.
- **Fishtank password:** read it with `config.fishtank_password(config)` (the `MSR_FISHTANK_PASSWORD` environment variable wins over `[Fishtank] password`), never `config.get(...)` directly.
- **Logs:** `redact_cmd_for_log` / `redact_for_log` strip `jwt=`, tokens, Cookie/Authorization. `RedactLogFilter` on the root logger **and on every handler** (file, console, the GUI `QueueLogHandler`) also redacts stderr lines, exception text, and `%(channel)s` (custom URLs with `?jwt=`). A logger filter does not see records propagated from named child loggers, so a new handler must get `_ensure_redact_filter(handler)` / `addFilter(RedactLogFilter())`. Do not log raw Fishtank auth JSON.
- **Network ffmpeg** (`platforms.py`): protocol whitelist is `http,https,tcp,tls,crypto,hls` — **no `file`**. Direct ffmpeg (Fishtank/Rumble HLS/CMAF) uses `-protocol_whitelist`. yt-dlp recordings pass the same list as `--downloader-args ffmpeg_i:…` (must be `ffmpeg_i`, not `ffmpeg:`, or yt-dlp appends it after `-i`). Local clip/remux reads do not use that whitelist.
- **Channel keys:** `parse_channel_key` allowlists platforms. Kick is a bare name — `:` `/` `\\` are rejected so `..\..\Users\Public:out` cannot become a platform directory. Custom URLs must be `http://` or `https://`. `coerce_channel_records` re-validates `channels.json` on load; `record_worker` refuses unsafe keys. `channel_key_to_dirs` returns `('unknown', 'unknown')` for garbage instead of joining raw `..`.
- **In-app update:** banner click runs `msr.update.prepare_update` (GitHub zipball, allowlisted extract) then `_full_quit(after_children=spawn_updater)`. Spawn the helper **after** killing children or `_full_quit` will kill it. Helper is `msr/apply_update.py` copied to temp (stdlib only, no `msr` import). Never overwrite `config.ini` / `channels.json` / `cookies.txt`. HTTPS GitHub hosts only. `apply_staged_update` is all or nothing: it compiles every staged `.py`, backs up the current program files to `msr_update_backup/`, compares each copied file byte for byte, and on any error puts the backup back and removes files the update added (`rollback`). A changed `requirements.txt` leaves `msr_update_notice.txt`, shown once at the next start. Test with a fake zip and a patched `urlopen` (`tests/test_hardening.py`), never a real install.
- **Single instance** per `streams_dir`: `try_acquire_single_instance` in `main()` (Windows mutex / POSIX flock). A second launch focuses the existing `Multi-Stream Recorder v…` window and exits; `--headless` prints and exits 1. Do not skip this or two GUIs will record the same cameras.
- **`kill_orphan_recording_processes`** (old name `kill_orphan_ffmpeg_processes` still wraps it) uses `psutil` from `msr.deps`. Pass `streams_dir`. Kill leftover **`record_worker` spawn processes** (and their capture tree), not only ffmpeg — ffmpeg SIGTERM is a reconnect. Skip local remux/clip (no http) and unrelated encodes. Called at startup, `StreamRecorder.stop()`, and `_full_quit`. Never kill `keep_pid`’s tree.
- **Orphan matching is by folder, not text:** `streams_dir` may be a list (main + fallback, `StreamRecorder._orphan_roots()`); `_is_instance_path` accepts only the root itself or `Recorded`/`processed`/`PendingDeletion`/`Clips`/`stream_recorder.log*`/`.msr_instance.lock` under it (so `streams2`, `streams-test` and a nested instance are not ours), and `_plan_orphan_kills` skips a spawn worker whose `parent_pid` is alive and not ours. Never go back to `str in str`. Unreadable/unknown = not an orphan.
- **Supervisor (`StreamRecorder._supervise_tick`):** every kill we do goes through `_mark_killed`/`_supervision()["killed"]` (pids), and `stop_channel` adds to `stopped_channels` *before* killing. A worker exit not in that set is a crash (exit code 15 is NOT "ours": psutil kills look the same). Quick exits (< `RESTART_FAST_SECONDS`) back off `RESTART_BACKOFF_FIRST`..`RESTART_BACKOFF_MAX`. The `run()` loop wraps each pass in `try/except` and must never end on an exception; `update_status_from_queue` is also called by the GUI and must not raise.
- **Child processes never get a console window:** every `subprocess.run/Popen` in `msr/` passes `**no_window_kwargs()` (`msr/nowindow.py`, stdlib only; `no_window_kwargs(extra_flags)` ORs CREATE_NO_WINDOW onto e.g. a priority class, and is `{}` off Windows). `import msr.nowindow` also patches `Popen` as a safety net. `tests/test_no_console.py` scans the source and fails on a launch without it; the only exceptions are its allowlist (detached relaunch/updater, the `run_msr.pyw` launcher, Notepad and Explorer/open for the user). Never pass `creationflags=` alone: it used to turn the default off.
- **Keep worker start-up light:** a spawned worker re-runs `Multi-Stream-Recorder.py` as `__mp_main__`, so its GUI-side imports sit under `if __name__ != "__mp_main__":`; do not add top-level imports there that a worker does not need. `msr.deps` probes yt-dlp/streamlink/ffmpeg/deno once (in parallel) in the main process and passes the result to workers in `MSR_TOOL_VERSIONS`; `HAS_TRAY`, `pystray`, `Image`, `ImageDraw`, `HAS_NOTIFICATIONS` and `plyer_notification` load on first access. `tests/test_startup_cost.py` checks that a worker loads no tkinter, GUI, pystray, PIL or plyer and starts no probe processes. Use `psutil._psplatform.ppid_map()` via `util._ppid_map()` rather than per-process `ppid` in process scans (about 1 s for 300 processes on Windows).
- **Footage is never deleted, moved or replaced before its replacement is verified.** `remux_to_mp4` writes `<mp4>.part` (`-f mp4`, `storage.remux_part_path`), runs `verify_remux_output` (exists, >= `MIN_MP4_BYTES`, readable duration, within max(5 s, 2 %) of the source; a shorter duration with >= 90 % of the size is accepted with a warning because live-capture PTS jumps make the source length unreliable) and `os.replace`s it onto the final name; every failure removes the `.part` and leaves the `.ts` and any existing MP4 alone. The cleanup passes use the same check before trusting an existing MP4 and keep the `.ts` on failure; only `"output too small"` goes to PendingDeletion. `_run_remux_cmd` has a stall/cancel watchdog. Test remux/probe flows with `tests/fake_ffmpeg.py` (`FakeFfmpeg(tmp, "ok" | "fail" | "truncate" | "no_moov" | "hang" ...)`, `write_media`, `fake.installed()`); set `MSR_REAL_FFMPEG` to a folder with ffmpeg/ffprobe to also run `RealFfmpegTests` on synthetic clips.
- **Startup cleanup** (`StreamRecorder.run` in `msr/recorder.py`): `_plan_startup_cleanup()` snapshots leftover `.ts` files BEFORE the workers launch; `_launch_startup_cleanup()` remuxes that snapshot afterwards on the `StartupCleanup` thread (below-normal ffmpeg via `remux_to_mp4(low_priority=True, cancel_event=...)`, one file at a time, `_cleanup_lock` per file, cancelled by `stop()`). Never scan live folders from this path; only snapshot files are processed. A `filename_pattern` without a timestamp falls back to the synchronous order. Tests: `tests/test_startup_cleanup.py`.
- **`record_worker` imports:** `random`, `sanitize_path_component`, `custom_url_folder_names`, `parse_channel_key`, `redact_for_log`, `text_progress_bar`, `find_cookies_file`, `ffprobe_from_ffmpeg`, `parser_getfloat` / `parser_getint` / `parser_getboolean`, `default_streams_dir`. Missing any of these is a spawn-loop `NameError`.
- **Startup order and failure paths** (`main()`): `Config` (never raises on a bad file) then `setup_logging` (`resolve_log_dir` falls back to the current folder, then temp, when the recordings folder or its drive is unusable, so it cannot raise) then `validate_startup` (the friendly `Drive ... does not exist` / `Cannot create streams directory` / ffmpeg errors, shown through `startup_error.report_failure`). Do not add code before `validate_startup` that needs `streams_dir` to exist. Headless exit goes through `recorder.finish_headless_session` (stop, `wait_for_cleanup`, Manager shutdown); the signal handler only raises `KeyboardInterrupt`, it must not stop or exit itself.
- **Drive loss:** workers read `fallback_dir` from the config dict; `recorded_path`/`processed_path`/`pending_dir` are rebound only at the top of the loop (a background remux gets its own copy), the reconnect group is dropped on a switch, and an `OSError` that means the drive is gone (`storage.is_drive_error`) skips the crash back-off. Any new write of an app file should go through `history.atomic_write` and `storage.write_failed`, not a bare `except: pass`. The `--json` status never creates folders (`_drive_available` only checks the drive).
- **`streams_dir` default** is `default_streams_dir()` (`%USERPROFILE%\Videos\Multi-Stream Recorder` / `~/Videos/Multi-Stream Recorder`), not `E:\Streams`. Never overwrite an existing `streams_dir` in `config.ini`.
- **Config coercion:** `Config._coerce_values` rewrites unparseable/out-of-range numbers and bools to defaults before workers spawn. Workers still use `parser_get*` so a bad dict cannot `ValueError` on `getfloat`. Do not warn “using default” without actually setting the value.
- **Custom URL folders:** `custom_url_folder_names()` is the single mapping used by `record_worker` and `channel_key_to_dirs`. Chaturbate-style `https://site.com/user/` goes to `custom/site/user/`. No path username → keep the old `custom/site/` bag. TikTok custom URLs stay `custom/<handle>/` (do not nest under `tiktok/`, existing files live there). Background cleaner walks one extra directory level so both the bag and nested user folders are remuxed.
- **Cookie dots** redraw from tree events / `yview`, not a 500ms idle loop.
- **Disk / NIC meters** (a thin right-aligned row under the Status header: the header's four buttons already fill it at the 1100 px default and the meter was being clipped to ~120 px) are whole-disk write and whole-NIC download from `psutil`. MSR-only write rate uses worker `size_bytes` on the status dict — do **not** `listdir` the recordings folder on the GUI 1s tick. Tooltip holds stream Mbps from the status detail string. Hidden when `psutil` is missing. Sample with `root.after(1000)`. On Windows, map `streams_dir` to `PhysicalDriveN` via `IOCTL_STORAGE_GET_DEVICE_NUMBER`.
- **Stop Recording** / per-channel stop join process trees on a background thread. Do not call `recorder.stop()` or `stop_channel()` on the Tk thread (the GUI freezes for 10s×N). `_full_quit` may still stop synchronously before `os._exit`.
- **Bottom toolbar** packs `side=RIGHT` (first = rightmost). Pack each combobox *before* its label so the caption sits to the left of *that* dropdown: `Clip Length: [combo]  Polling: [combo]  Theme...`. Do not pack the label first — that put “Clip Length:” on the poll combo and “Check Now” on the clip combo.
- **GUI log queue** is bounded (`Queue(maxsize=2000)`, drop-oldest). Do not use an unbounded `Queue`.
- **`check_disk_space`** fails closed when the path is not writable. Do not `return True, 0` on `disk_usage` errors.
- **Kick records with streamlink.** Do not log “yt-dlp failed” on a missing Kick file; the retry is another streamlink argv.
- **ffprobe path** is `ffprobe_from_ffmpeg()` in `msr/util.py`. Do not `ffmpeg_path.replace("ffmpeg", "ffprobe")`.
- **Cookies path:** `application_dir()` is the launcher directory, not `msr/`.
- **Fishtank JWT refresh** in `platforms.py` needs `import threading`.
- **Fishtank cameras** change every season (and in the off-season). Keep `CAMERA_ALIASES` as a convenience snapshot; do not scrape `fishtank.live` HTML (Next.js CSR). Catalog is `GET /v1/live-streams`. Login/HLS URL shape stays. Accept raw stream ids (`is_fishtank_stream_id`, e.g. `bar-5`, `computer-lab2-5`, `director-as-seen-on`) so a new season does not require a code edit. Add aliases when a season's catalog is confirmed; do not delete old ones. As Seen On (2026-09) remapped `director` to `director-as-seen-on`; keep `dirc` → `dirc-5`.
- **Open in Browser** goes through `channel_watch_url()` — do not hardcode Kick as the fallback for prefixed platforms.
- **Rumble cookie domain** is `rumble.com`, not Kick.
- **Rumble 403:** record the channel-page HLS URL with ffmpeg (`build_recording_command_rumble_hls`) when `videos[].url` is in the page JSON. Otherwise yt-dlp must use `--impersonate chrome` on the *first* video-page fetch (plain dump-json 403s). Do not tell the user their cookies expired for that first 403. `parse_rumble_channel_html` must capture the **whole** `<script type="application/json">` body (`(.*?)` inside the tag), not `\{.*?\}` which stops at the first nested `}` and drops the HLS URL.
- **Chaturbate / CMAF:** split video+audio playlists go through `build_recording_command_ffmpeg_merge`, not yt-dlp live merge. A 15s clip must contain **both** h264 and AAC.
- **TikTok offline fallback** (`check_tiktok_live_webcast`): yt-dlp `"not currently live"` is not authoritative for 24/7 LIVEs. Try `/api-live/user/room?uniqueId=` first (no roomId needed), then `roomId` on the profile **and** `/@user/live`, then `webcast.us` / `webcast.tiktok.com`. Status 2 = live; leftover roomId with status 4 is not. Log misses at **info**, not debug.
- **Cookies:** MSR never refreshes `cookies.txt`. It only reads it (roster dots every 5 minutes) and passes `--cookies` to tools. User re-exports from the browser. Do not replace the whole jar with a Rumble-only dump — merge would wipe YouTube/Twitch/Kick/TikTok rows.
- **Git:** ignore `config.ini`, `config.ini.broken-*`, `msr_startup_error.log`, `cookies.txt`, `channels.json`, `window_state.json`, `kick_channel_ids.json`, recordings dirs, `.venv/`, `venv/`, `.msr_write_probe`. Do **not** ignore `msr/`, `tests/`, `AGENTS.md`, `CHANGELOG.md`, `SECURITY.md`, `.github/`, or `channels_fishtank.json`.
- **`main_gui` is one closure.** A widget or function name bound twice there silently replaces the first for every other function (a second `filter_entry` made `apply_theme` crash on start; under `pythonw` that looks like a window that flashes and vanishes, with no log line). Give new widgets a unique prefix. `tests/test_gui_smoke.py` fails on duplicate names and launches the real window hidden (`MSR_SMOKE_TEST=1`, dark and light) against a temp data dir. To see a startup traceback, run with `python` (not `pythonw`) from a console.
- Worker status while recording includes **`size_bytes`** (int) for the header meter. Do not drop that field; the GUI must not `listdir` recording folders on the 1s tick.

## Run

```
python Multi-Stream-Recorder.py
python Multi-Stream-Recorder.py --headless
python -m unittest discover -s tests -t .
```
